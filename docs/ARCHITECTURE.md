# Architecture and design

This documents what `devoid.sh` on `progressive-refactor` **attempts** to do. It is an opinionated, hardware-specific Debian installer, not a multi-distribution framework.

## Host and target phases

```text
UEFI Debian live host (ROOT)
   │ install prerequisites, verify YubiKey and TPM2
   ├─ wipe disk → GPT → 10 GiB FAT32 ESP + LUKS2/XFS root
   ├─ root passphrase, FIDO2 and initial TPM2 enrollment
   ├─ bootstrap Debian with mmdebstrap
   ├─ extract selected SHA-256 EFI service-driver digests from TPM log
   └─ unshare + systemd-nspawn (raw device, USB, TPM, efivars passed through)
          ├─ PAM U2F root authentication; Zsh
          ├─ kernel-install + dracut + ukify
          ├─ signing keys/certificate and PKCS#11 PIN helper
          ├─ signed fallback and DKMS signing hook
          ├─ firmware db → KEK → PK
          └─ swapfile, home helper, post-boot TPM helper
   │
   ├─ replace firmware boot entries; copy NetworkManager profiles
   └─ unmount root/ESP, close LUKS mapper
```

The privileged target container is **not a security sandbox**; the host binds firmware variables and devices into it. The same source script enters its `target` mode there.

## Storage

- Partition 1: 10 GiB FAT32 EFI system partition (`/boot/efi`).
- Partition 2: all remaining space, LUKS2, mapped as `cryptoroot`, containing one XFS root filesystem.
- 8 GiB swapfile under the encrypted root, listed in `/etc/fstab`.
- Optional 100 GiB LUKS-backed `ext4` homed user image. No dedicated `/home` partition.

LUKS2 has a recovery passphrase, a FIDO2 enrollment and TPM2 enrollment using PCR 7. A generated `/root/tpm-enroll.sh` refreshes the TPM policy on the installed system. PCR 7 reflects **Secure Boot state**, not the digest of all installed binaries.

## Secure Boot policy and UKIs

```text
owner-controlled firmware PK / KEK / db
   ├─ owner's signing certificate in db
   └─ explicitly enrolled SHA-256 digests of selected EFI service drivers
        ↓
signed fbx64 fallback loader (EFI/BOOT/BOOTX64.EFI)
        ↓
signed UKI (EFI/Linux/*.efi)
   kernel + dracut initramfs + embedded command line
        ↓
LUKS2 root → XFS
```

The installed kernel pipeline uses `layout=uki`, `dracut` and `ukify`; a postinstall hook signs UKIs. `BOOTX64.CSV` boot hints are generated by a second hook. A local `dpkg-divert` disables Debian's original dracut postinstall hook. Package upgrades and kernel hooks must continue to cooperate with PKCS#11 signing.

The signing identity is an X.509 certificate plus a **private key held by the YubiKey PIV 9c slot** (object ID `02`). The certificate is copied into `/etc/kernel/keys/`; a separate `openssl-signing.cnf` there is supplied only to signing commands. The PIN is cached in a root kernel session keyring under `devoid:piv-pin`, or prompted when unavailable. This configuration is local to signing and should not be exported globally as `OPENSSL_CONF`: other programs using OpenSSL, including Node/Codex, can fail with that environment setting.

The script configures a DKMS `sign-file` helper using the same key, but that integration needs kernel/version-specific verification. On-device *touch* policy is configured outside the script, and must be tested rather than presumed.

## Measured EFI service drivers

The host reads `/sys/kernel/security/tpm0/binary_bios_measurements` using `tpm2_eventlog`, selects SHA-256 digests from events whose type contains `SERVICES_DRIVER`, deduplicates them, converts each digest into an EFI Signature List, and **appends** that list to `db`. This authorizes exactly matching binary images; measurements are **not proof that the drivers are benign**.

The script attempts to clear immutable attributes on `db`, `KEK` and `PK` efivarfs files before enrollment, and installs `PK` last. Firmware behavior and successful boot after replacement need independent testing; drivers or external media trusted only by the old databases may cease functioning. It removes existing firmware boot entries except those containing “debugging”.

## PAM and home encryption

The root password remains configured. `pam_u2f.so` is prepended as an **auth sufficient** rule for `su`, `su-l` and `login`, preserving the distribution's existing PAM stacks. A valid root password may still authenticate through the fallback rules; the system does **not** guarantee key-only login.

`systemd-homed` creates separate LUKS-backed ext4 homes with PIN/presence FIDO2 policy and a per-user recovery key. Files are plaintext to authorized processes while a home is active.

## Out of scope

The portable `devoid-usb.sh` is intentionally **unsigned and unencrypted**, with a generic dracut initramfs, portable systemd-boot and no firmware NVRAM manipulation. See [USB.md](USB.md). Token2 OpenPGP/Scute PKCS#11 signing is documented as a working **separate experiment**, not integrated as an installer replacement for YubiKey PIV.

For threats and recovery, see [SECURITY.md](SECURITY.md) and [RECOVERY.md](RECOVERY.md).
